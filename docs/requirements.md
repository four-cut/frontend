# 찍고갈래? 요구사항 정의서

> v0.1 · 2026-08-20
> 기준 자료: Figma「나만의 네컷 클론코딩」 앱 디자인 시안 15장 (`src/assets/samples/`)

사용자가 앱으로 **8장을 연속 촬영**하고, 그중 레이아웃에 맞는 장수를 골라 **네컷 스트립으로 합성**한 뒤, **기기에 저장하거나 인쇄**하는 것이 제품의 핵심 흐름이다. 오프라인 네컷 부스의 경험을 개인 기기로 옮긴 형태다.

---

## 1. 범위

### 포함

- 촬영 플로우 전체 — 안내 → 레이아웃 선택 → 촬영 → 사진 선택 → 로고 선택 → 출력
- 세로형(4컷)·가로형(3컷) 두 레이아웃과, 가로형 진입 시 기기 회전 유도
- 스트립 이미지 합성 및 기기 저장
- OS 인쇄 시트 호출

### 제외

- **인쇄 설정·용지 크기 화면** — 아래 참고
- 서버·계정·공유 기능 (시안에 근거 없음)

> **확인 필요 — 인쇄 화면 2종은 OS 제공 UI로 판단됨**
>
> 시안 `Frame-6 / 7 / 12 / 13`(프린터·매수·용지 크기)은 앱 화면이 아니라 **iOS AirPrint 시스템 시트**로 보인다. 근거는 세 가지다.
>
> 1. 다른 화면은 전부 둥근 고딕 디스플레이 폰트인데 이 넷만 시스템 폰트다.
> 2. iOS 특유의 파란 체크마크와 회색 disclosure chevron을 쓴다.
> 3. `선택한 프린터 없음`과 `4 x 6인치 / 엽서 / A6 / PRC 32K`는 AirPrint의 기본 문자열·용지 목록 그대로다.
>
> 사실이라면 **인쇄하기 버튼은 네이티브 print API 호출만 하면 된다.** → `OQ-09`

## 2. 용어

| 용어 | 정의 |
| --- | --- |
| **컷** | 스트립에 배치되는 사진 한 장. 세로형 4컷, 가로형 3컷 |
| **레이아웃** | 컷의 배치 방식. `세로형`(세로 사진 2×2) 또는 `가로형`(가로 사진 3단 적층) |
| **스트립** | 컷과 로고를 합성한 최종 출력물. **레이아웃과 무관하게 항상 세로 방향 용지** |
| **촬영본** | 촬영 단계에서 찍은 8장의 원본. 이 중 컷 수만큼 선택 |
| **로고** | 스트립 하단에 들어가는 브랜드 마크. 기본값은 앱 로고 |

> **주의 — 가로형이어도 용지는 세로다.**
> 가로형 시안(`Frame-11 / 12`)의 미리보기를 보면, 기기는 가로로 눕혀 촬영하지만 결과 스트립은 **세로 용지에 가로 사진 3장이 쌓인 형태**다. 즉 「가로형」은 *용지 방향*이 아니라 *각 컷의 사진 방향*을 뜻한다. 합성 로직에서 이 구분을 놓치면 전체가 틀어진다.

## 5. 화면별 요구사항

### SR-01 · 홈 — `MainTabs/Shoot/Home`

- **구성** 중앙 로고 + 워드마크 「찍고갈래?」, 하단 CTA 2개, 하단 탭바
- **동작** `촬영하기` → SR-02 / `프레임 만들기` → SR-09 (`OQ-03`)

### SR-02 · 안내사항 — `MainTabs/Shoot/Guide`

- **구성** 좌상단 뒤로가기, 제목 「안내사항」, 번호 목록 3항목, 하단 CTA, **탭바 유지**
- **본문**
  1. 타이머는 6초
  2. 촬영하기 누르면 바로 촬영
  3. QR로 사진, 영상 저장
- **동작** `레이아웃 고르기` → SR-03. 뒤로가기 → 홈
- **비고** 본문 3번이 QR 저장을 명시하나 해당 화면 시안이 없음 → `OQ-02`

### SR-03 · 레이아웃 선택 — `CaptureFlow/LayoutSelect`

- **구성** 좌상단 뒤로가기, 전체 폭 카드 2장, **탭바 없음**
- **카드**
  - `세로형` — 검정 라운드 카드 안에 흰 세로 시트, 2×2 격자 슬롯 4개
  - `가로형` — 검정 라운드 카드 안에 흰 세로 시트, 가로 슬롯 3단
- **동작** 세로형 → SR-05 (컷 수 4) / 가로형 → SR-04 (컷 수 3)
- **상태** 선택한 레이아웃은 플로우가 끝날 때까지 유지. SR-06의 선택 장수와 SR-07의 합성 배치가 이 값에 의존

### SR-04 · 회전 안내 — `CaptureFlow/RotateGuide`

- **구성** 화면 중앙에 회전 아이콘과 「기기를 돌려주세요!」 한 줄. 다른 요소 없음
- **에셋** `images.refresh`
- **동작** 기기가 가로로 회전되면 자동으로 SR-05 진입
  *(자동 전환은 추론 — 시안에 버튼이 없어 다른 진행 수단이 없음)*

### SR-05 · 촬영 — `CaptureFlow/Capture`

- **구성**
  - 상단 중앙 대형 카운트다운 숫자 (시안 표기 `5`)
  - 하단 진행 카운터 `n/8`
  - 하단 `바로촬영` 버튼과 원형 카메라 전환 버튼
  - 배경은 카메라 프리뷰 *(시안은 흰 배경이나 실제로는 프리뷰)*
- **동작**
  - 컷마다 6초 카운트다운 후 자동 촬영 *(6초는 SR-02 본문 근거)*
  - `바로촬영` — 카운트다운을 기다리지 않고 즉시 촬영
  - 전면 ⇄ 후면 전환
  - **총 8장** 완료 시 SR-06 자동 이동
- **에셋** `images.cameraFlip`
- **방향** 세로형은 세로, 가로형은 가로 고정. 촬영본의 사진 방향이 레이아웃과 일치해야 함

### SR-06 · 사진 선택 — `CaptureFlow/PhotoSelect`

- **구성**
  - 좌상단 홈 버튼, 제목 「사진을 선택해주세요」
  - 상단 스트립 미리보기 — 선택이 실시간 반영되고 **빈 슬롯은 회색**
  - 중단 `사진 선택 (n/N)` 카운터
  - 하단 촬영본 8장 가로 스크롤, `다음` 버튼
- **동작**
  - N = 레이아웃 컷 수 (세로형 4 / 가로형 3)
  - 촬영본을 탭하면 **선택 순번 배지**가 붙고, 그 순번이 스트립 내 위치를 결정
  - N장을 모두 채워야 `다음` 활성화
  - 홈 버튼 → 플로우 종료 후 홈 복귀 (중단 확인 여부 → `OQ-06`)
- **에셋** `images.home`
- **가로형 차이** `Frame-10`은 좌측 스트립 미리보기 / 우측 촬영본 격자의 2단 구성

### SR-07 · 로고 선택·출력 — `CaptureFlow/LogoSelect`

- **구성**
  - 좌상단 홈 버튼
  - 완성된 스트립 미리보기 — 하단에 로고 마크 합성된 상태
  - 「커스텀 로고 선택」 원형 칩 목록 (`kakao`, `KWDC`)
  - CTA 2개 — `인쇄하기`, `사진, 영상 저장하기`
- **변형** `Frame-4`는 로고 칩 대신 아웃라인 박스 「프레임 만들기」. 커스텀 로고가 없을 때의 빈 상태로 보이나 확정 필요 → `OQ-03`
- **동작**
  - 로고 칩 선택 시 스트립 하단 마크 교체, 미리보기 즉시 반영
  - `인쇄하기` → 합성 이미지를 OS 인쇄 시트로 전달 (EXT-01)
  - `사진, 영상 저장하기` → 기기 앨범 저장. 「영상」의 정의는 `OQ-01`
- **합성 규칙** 출력 시트는 **레이아웃과 무관하게 세로 방향**. 세로형은 세로 사진 2×2, 가로형은 가로 사진 3단 적층, 두 경우 모두 하단에 로고 영역

### SR-08 · 갤러리 — `MainTabs/Gallery`

현재 「갤러리」 텍스트만 있는 자리표시자. **시안이 없어 요구사항 정의 불가** → `OQ-05`

### SR-09 · 프레임 만들기

홈의 두 번째 CTA와 `Frame-4`의 아웃라인 박스에 같은 문구가 등장한다. **시안이 없어 정의 불가.** 두 진입점이 같은 기능인지부터 확인 필요 → `OQ-03`

## 6. 공통 요구사항

### CR-01 · 네비게이션 구조

탭바 표시 여부가 명확한 경계를 만든다. 하단 탭만으로는 이 구조를 표현할 수 없으므로 스택을 중첩한다.

| 계층 | 포함 화면 | 탭바 |
| --- | --- | --- |
| `RootStack › MainTabs › Shoot` | SR-01 홈 → SR-02 안내사항 | 있음 |
| `RootStack › MainTabs › Gallery` | SR-08 갤러리 | 있음 |
| `RootStack › CaptureFlow` | SR-03 → SR-04 → SR-05 → SR-06 → SR-07 | 없음 |

CaptureFlow는 탭바를 덮어야 하므로 탭 내부가 아니라 **루트 스택에 형제로** 놓인다.

### CR-02 · 촬영 세션 상태

CaptureFlow 전체가 공유하는 상태. 화면 간 파라미터로 넘기기보다 플로우 스코프의 단일 상태로 둔다.

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `layout` | `'portrait' \| 'landscape'` | SR-03에서 결정 |
| `cutCount` | `number` | `layout`에서 파생 (4 또는 3) |
| `shots` | `string[]` | 촬영본 8장의 경로 |
| `selection` | `number[]` | 선택 순번이 반영된 촬영본 인덱스 |
| `logo` | `string \| null` | 선택한 로고 (기본값 앱 로고) |

Provider를 CaptureFlow 네비게이터 안에 두면 플로우를 벗어날 때 상태가 자동으로 정리된다.

### CR-03 · 타이포그래피

시안의 제목·버튼은 모두 **둥근 고딕 디스플레이 서체**이고, 이것이 브랜드 아이덴티티의 핵심이다. 현재 `src/theme/typography.ts`의 `regular` · `bold` · `display`가 모두 `undefined`라 시스템 폰트로 렌더링된다.

> **순서가 중요하다.** 폰트를 나중에 넣으면 자간·행간이 달라져 이미 만든 화면의 레이아웃을 전부 다시 만져야 한다.

### CR-04 · 화면 방향

- 앱 기본은 **세로 고정**
- SR-04에서 가로 감지를 허용하고, 가로형 플로우(SR-05~07)는 가로 고정
- 플로우 종료 시 세로 고정 복귀

### CR-05 · 권한

- **카메라** — SR-05 진입 전 요청. 거부 시 처리 방침 필요 → `OQ-07`
- **미디어 저장** — SR-07 저장 시점 요청. Android 13+ 는 `READ_MEDIA_IMAGES` 기준

### CR-06 · 에셋 매핑

`src/assets/index.ts`에 등록됐지만 미사용인 4개가 미구현 화면에 정확히 대응한다. **새로 export 받을 에셋은 없다.**

| 에셋 | 사용처 |
| --- | --- |
| `chevronBack` | SR-02 · SR-03 좌상단 뒤로가기 |
| `home` | SR-06 · SR-07 좌상단 홈 버튼 |
| `cameraFlip` | SR-05 카메라 전환 버튼 |
| `refresh` | SR-04 회전 아이콘 |

## 8. 신규 의존성

네이티브 모듈은 추가할 때마다 Gradle 재빌드가 필요하다. 첫 빌드는 약 4분 30초였다.

| 용도 | 후보 | 재빌드 | 관련 |
| --- | --- | --- | --- |
| 스택 네비게이션 | `@react-navigation/native-stack` | 불필요 | CR-01 |
| 카메라 | `react-native-vision-camera` + `react-native-nitro-modules` + `react-native-nitro-image` | **필요** | SR-05 |
| 스트립 합성 | `@shopify/react-native-skia` | **필요** | SR-07 |
| 앨범 저장 | `@react-native-camera-roll/camera-roll` | **필요** | SR-07 |
| 인쇄 | `react-native-print` | **필요** | EXT-01 |
| 방향 제어 | `react-native-orientation-locker` | **필요** | CR-04 |

합성은 **Skia 오프스크린 렌더링**으로 정했다. 화면 캡처(`view-shot`) 방식은 결과물이 화면 해상도에 묶여 NFR-02를 만족할 수 없다.

미리보기(`StripPreview`)와 합성(`composeStrip`)이 **같은 `stripGeometry()`** 를 쓴다. 배치 계산이 한 곳에만 있어야 화면과 출력물이 어긋나지 않는다. 시트 비율은 시안의 흰 시트 118×214에서 가져왔고, 인쇄 폭 1200px 기준으로 **1200×2176px**이 나온다.

### Windows 빌드 주의사항

vision-camera 5.x를 붙이면서 겪은 것들이다.

**peer dependency 2개를 직접 설치해야 한다.** `react-native-nitro-modules`와 `react-native-nitro-image`가 없으면 `Project with path ':react-native-nitro-modules' could not be found`로 Gradle 평가 단계에서 실패한다.

**`ninja: manifest 'build.ninja' still dirty after 100 tries`.** Windows에서 NDK/CMake가 긴 경로를 만나면 CMake 재생성이 무한 반복된다. `node_modules/*/android/.cxx`를 지우고 ABI를 줄여 빌드하면 넘어간다.

```sh
./gradlew assembleDebug -PreactNativeArchitectures=x86_64   # 에뮬레이터 전용
```

에뮬레이터 개발에는 `x86_64` 하나면 충분하고 빌드도 4분 30초 → 1분 20초로 줄어든다. **다만 이건 우회일 뿐이라 4개 ABI를 모두 담는 릴리스 빌드에서는 다시 터질 수 있다.** 릴리스 전에 Windows 긴 경로 지원을 켜거나 CI를 Linux/macOS로 돌리는 편이 안전하다.

**jest에서 네이티브 모듈을 못 찾는다.** nitro가 import 시점에 TurboModule을 조회해서 실패하므로 `__mocks__/react-native-vision-camera.js`로 대체했다.
