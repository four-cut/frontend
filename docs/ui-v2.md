# 결과 화면 UI 개편 (UI-V2)

오프라인 테스트에서 나온 지적을 Material 3 / iOS HIG 기준으로 고친 시안이다.
**결과 화면(`LogoSelectScreen`) 한 곳에만 적용했다.** 다른 담당자 화면은 그대로다.

## 왜 손댔나

기존 화면이 어색했던 건 취향 문제가 아니라 세 가지 구조적 원인이 있었다.

1. **굵기가 하나뿐인 폰트.** Jua 한 종류로 제목·본문·버튼을 다 그린다. 두 가이드라인 모두
   위계를 굵기 + 크기로 만드는데 굵기 축이 없으니 크기만으로 버티다 제목이 34까지 커졌다.
   → Pretendard(SIL OFL) 세 굵기를 넣어 해결했다.
2. **큰 타입 스케일.** 제목 34 / 본문 21 은 키오스크 크기다. 상용 사진앱은 제목 24~28 / 본문 16~17.
3. **강조색 부재.** 팔레트가 흑·백·회색뿐이라 "선택됨"을 나타낼 수단이 없었다.
   프레임을 골라도 티가 안 나던 게 이것 때문이다.

## 무엇을 바꿨나

| 지적 | 처리 |
| --- | --- |
| 프레임이 어떤 모양인지 눌러봐야 앎 | 바텀시트 3열 그리드. 미리보기가 없으면 슬롯 모양을 그린다 |
| 프레임 목록이 자리를 너무 먹음 | 평소엔 안 보이고, 버튼 하나로 연다 |
| 여러 개를 고르기 불편 | 시트 안에서 스크롤. 고른 항목은 강조색 테두리 + 체크 배지 |
| 인쇄·공유가 항상 떠 있음 | 상단 바 아이콘으로 이동 (터치 영역 48dp) |
| 버튼이 너무 많음 | 하단은 주 동작(QR) 하나 + 보조(저장) 하나 |
| — | 저장 결과를 스낵바로. 전에는 글이 뜰 때마다 아래 버튼이 밀렸다 |
| — | 결과물 미리보기를 키움 (화면 폭의 0.52 → 0.62) |
| — | UI 서체를 Pretendard 로. Regular/SemiBold/Bold 세 굵기로 위계를 만든다 |

타입 스케일·간격·색 값은 `src/theme/uiV2.ts` 에 근거와 함께 적어 뒀다.

## 서체

`assets/fonts/` 에 Pretendard 세 굵기(Regular/SemiBold/Bold, 합 7.7MB)를 넣고
`npx react-native-asset` 으로 링크했다. 라이선스는 SIL OFL 이고 전문을
`assets/fonts/Pretendard-LICENSE.txt` 에 함께 뒀다.

워드마크("찍고갈래?")는 브랜드라 Jua 그대로다. 공용 `typography.ts` 는 건드리지 않았고,
새 서체는 `uiV2.ts` 의 `fontsV2` 로만 쓴다 — 다른 화면은 지금도 Jua 다.

**폰트를 추가했으므로 이 브랜치를 받으면 Android 재빌드가 필요하다.**

## 되돌리는 법

전부 되돌리려면:

```bash
git revert <이 PR 의 머지 커밋>
```

부분만 되돌리려면 — 아래 세 곳이 전부다.

1. `src/theme/uiV2.ts` 삭제
2. `src/components/v2/` 폴더 삭제
3. `src/screens/LogoSelectScreen.tsx` 에서 `UI-V2` 로 검색되는 부분 되돌리기

```bash
grep -rn "UI-V2" src/
```

**공용 `src/theme/` 값은 하나도 바꾸지 않았다.** 다른 화면이 같이 바뀌면 시안을 비교할 수 없고
되돌릴 범위도 커지기 때문이다. 팀에서 채택하면 `uiV2.ts` 를 공용 테마로 옮기면 된다.

i18n 에 추가한 키(`result.changeFrame`, `result.frameSheetTitle`, `result.frameNone`)도
`UI-V2` 주석을 달아 뒀다.

## 아직 안 한 것

- **일본어 굵기.** `AppText` 가 일본어일 때 Zen Maru Gothic 으로 갈아 끼우므로 굵기가
  적용되지 않는다. Pretendard 에는 가나·한자가 없어 섞어 쓸 수 없다. 일본어까지 주려면
  PretendardJP 가 필요한데 한자 때문에 한 벌에 수십 MB라 미뤘다.
- **화면 분리**(꾸미기 → 결과). 네비게이션 구조를 건드려야 해서 분리했다.
- **뒤로가기 확인창.** 플로우 전체에 걸리는 변경이라 따로 진행한다.
  React Navigation 7 의 `usePreventRemove` 로 처리하면 된다 — 그냥 막는 것보다
  "지금까지 찍은 사진이 사라집니다" 확인을 받는 쪽이 두 가이드라인에 맞는다.
